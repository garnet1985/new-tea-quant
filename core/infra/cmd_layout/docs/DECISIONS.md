# 命令行布局 — 设计与决策

**模块：** `infra.cmd_layout` · **版本：** `0.2.0`

**最低支持核心版本：** `>=0.5.0`

本文记录本模块的设计目标、方案思路与拍板决策。
相关：[ARCHITECTURE.md](./ARCHITECTURE.md)

---

## 设计目标

- **跨平台可读**：终端报告要在 Windows / Linux / macOS 上稳定可读，避免乱码。部分环境（如 Windows GBK 控制台）对方块、盒线支持差，曾出现乱码。
- **单一门面**：符合核心模块「单一门面」约定。历史上 `__init__` 曾再导出 `IconService` 与快捷函数 `i`，形成多入口。
- **图标可读回退**：在支持的终端显示直观图标，在不支持时仍给出可读标签。
- **标题层级清晰**：策略报告曾混用 `banner` + `separator` + `-- section --`，层级不清。

## 方案与思路

### 条形与分割线字符选型

| 方案 | 做法摘要 | 优点 | 缺点 |
|------|----------|------|------|
| A：Unicode 美观字符 | 方块 / 盒线 | 观感好 | 跨平台脆弱 |
| B：默认 ASCII（`#` / 空格 / `-` `=` `*`） | 填充与分割只用常见字符 | 稳定 | 观感朴素 |

最终拍板见下文 DEC-01。

### 门面导出范围

| 方案 | 做法摘要 | 优点 | 缺点 |
|------|----------|------|------|
| A：继续导出 IconService / i | 兼容旧 import | 迁移少 | 多真源 |
| B：只导出 `CmdLayout` | 图标走 `CmdLayout.icon.*` | 契约清晰 | 调用方改 import |

最终拍板见下文 DEC-02。

### 图标 emoji / ASCII 回退

检测终端能力后在 emoji 与 ASCII 双表间回退，与条形 ASCII 策略保持一致。拍板见下文 DEC-03。

### 连续样本的分桶渲染

连续样本在模块内走等宽分桶再渲染，覆盖主报告场景；复杂分桶仍可自建后 `render`。拍板见下文 DEC-04。

### 标题层级

固定四级标题 h1 / h2 / h3 / h4，替代此前混用的 `banner` + `separator` + `-- section --` 写法。拍板见下文 DEC-05。

---

## DEC-01：设计点 1：条形与分割线默认纯 ASCII

- **采用：** 方案 B
- **理由：** 布局模块优先可读与可移植
- **影响：** 调用方若强行传入自定义 Unicode `char`，自行承担终端风险

---

## DEC-02：设计点 2：只导出门面类 `CmdLayout`

- **采用：** 方案 B
- **理由：** 与 CORE_MODULE_STANDARDS 一致
- **影响：** 包根另保留短入口 `i`

---

## DEC-03：设计点 3：图标 emoji / ASCII 回退

- **采用：** 检测后回退 ASCII（`supports_emoji` + 双表）
- **理由：** 与条形 ASCII 策略一致
- **影响：** 未知图标名返回空串并打错误日志

---

## DEC-04：设计点 4：连续样本走等宽分桶再渲染

- **采用：** `from_values` 模块内等宽分桶
- **理由：** 覆盖主报告场景；复杂分桶仍可自建后 `render`

---

## DEC-05：设计点 5：标题四级 h1 / h2 / h3 / h4

- **采用：** 固定四级标题
- **h1：** 前空行 + 星号框（`print` 后再空行）
- **h2：** 前空行 + 正文 + `=` 下划线（宽 `max(正文显示宽, 24)`）
- **h3：** 前空行 + `--- 正文 ---`
- **h4：** 前空行 + `### 正文`
- **兼容：** `banner` / `section` 行为不变；新报告优先 h1–h4
- **影响：** 表与行内片段另见 `table` / `text` 命名空间
