**版本：** `0.2.0`

记录跨平台 ASCII 默认、门面导出、图标回退与标题层级等选型。术语见 [glossary.yaml](../glossary.yaml)。相关：[ARCHITECTURE.md](./ARCHITECTURE.md)

## 设计点 1：条形与分割线默认纯 ASCII

### 设计初衷

终端报告要在 Windows / Linux / macOS 上稳定可读，避免乱码。

### 设计背景

部分环境（如 Windows GBK 控制台）对方块、盒线支持差，曾出现乱码。

### 解决方案

| 方案 | 做法摘要 | 优点 | 缺点 |
|------|----------|------|------|
| A：Unicode 美观字符 | 方块 / 盒线 | 观感好 | 跨平台脆弱 |
| B：默认 ASCII（`#` / 空格 / `-` `=` `*`） | 填充与分割只用常见字符 | 稳定 | 观感朴素 |

### 决定

- **采用：** 方案 B
- **理由：** 布局模块优先可读与可移植
- **影响：** 调用方若强行传入自定义 Unicode `char`，自行承担终端风险

## 设计点 2：只导出门面类 `CmdLayout`

### 设计初衷

符合核心模块「单一门面」约定。

### 设计背景

历史上 `__init__` 曾再导出 `IconService` 与快捷函数 `i`，形成多入口。

### 解决方案

| 方案 | 做法摘要 | 优点 | 缺点 |
|------|----------|------|------|
| A：继续导出 IconService / i | 兼容旧 import | 迁移少 | 多真源 |
| B：只导出 `CmdLayout` | 图标走 `CmdLayout.icon.*` | 契约清晰 | 调用方改 import |

### 决定

- **采用：** 方案 B
- **理由：** 与 CORE_MODULE_STANDARDS 一致
- **影响：** 包根另保留短入口 `i`

## 设计点 3：图标 emoji / ASCII 回退

### 设计初衷

在支持的终端显示直观图标，在不支持时仍给出可读标签。

### 决定

- **采用：** 检测后回退 ASCII（`supports_emoji` + 双表）
- **理由：** 与条形 ASCII 策略一致
- **影响：** 未知图标名返回空串并打错误日志

---

## 设计点 4：连续样本走等宽分桶再渲染

### 决定

- **采用：** `from_values` 模块内等宽分桶
- **理由：** 覆盖主报告场景；复杂分桶仍可自建后 `render`

---

## 设计点 5：标题四级 h1 / h2 / h3 / h4

### 设计初衷

策略报告曾混用 `banner` + `separator` + `-- section --`，层级不清。

### 决定

- **采用：** 固定四级标题
- **h1：** 前空行 + 星号框（`print` 后再空行）
- **h2：** 前空行 + 正文 + `=` 下划线（宽 `max(正文显示宽, 24)`）
- **h3：** 前空行 + `--- 正文 ---`
- **h4：** 前空行 + `### 正文`
- **兼容：** `banner` / `section` 行为不变；新报告优先 h1–h4
- **影响：** 表与行内片段另见 `table` / `text` 命名空间
