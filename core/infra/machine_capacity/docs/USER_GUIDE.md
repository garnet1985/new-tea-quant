# Machine Capacity — 用户指南

**模块：** `infra.machine_capacity` · **版本：** `0.2.2`

**最低支持核心版本：** `>=0.5.0`

探测本机硬件——CPU 核数、内存大小、硬盘类型，回测引擎据此算 worker 数。  
相关：[README.md](../README.md) · [API.md](../API.md) · [ARCHITECTURE.md](./ARCHITECTURE.md)

---

## 功能总览

- 启动回测前自动探一遍你机器的 CPU、内存、硬盘（SSD 还是 HDD）
- 回测引擎据此决定开几个并行进程、给多少内存预算，尽量不卡死不爆内存
- 你一般感觉不到它——但"为什么回测只开了 N 个进程"就是它算的

## 配置说明

本模块只负责探测，无用户可配项。  
想手动干预并行度，改 `userspace/config/worker.json` 里的 `reserve_cores`（给系统预留几个核）等字段，回测引擎会结合探测结果一起算。

## 常见使用方式

### 场景 1：正常跑回测

1. 什么都不用做
2. 系统自动探测硬件并决定 worker 数
3. 机器越强，默认并行越多

### 场景 2：回测时电脑变卡

1. 在 `userspace/config/worker.json` 里把 `reserve_cores` 调大（比如从 1 调到 2）
2. 重跑回测，系统会少开进程，留出资源给日常操作

### 场景 3：觉得回测并行太少

1. 确认机器内存够大——内存预算不够时会被主动压低并行数
2. 检查 `worker.json` 里是否设了过保守的参数
3. SSD 上 IO 调度更激进，HDD 上偏保守，这是有意的

## 常见坑与注意事项

- **缺 `psutil` 时走回退值**：探测不到真实硬件，会按保守配置跑，并行偏少。装好 `psutil` 恢复
- **虚拟机 / 容器里核数不准**：读到的是分配额度不是物理机，worker 数按读到的算
- **回测中途别手动改硬件相关配置**：本次回测的并行计划启动时已定，改了下轮才生效
