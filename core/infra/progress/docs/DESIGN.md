# Progress — 设计

**版本：** `0.2.0`

进度文件的形状和写入方式。设计点 2 起取代设计点 1 的「一份当前进度」。  
相关：[ARCHITECTURE.md](./ARCHITECTURE.md)

---

## 设计点 1：所有业务共用一份当前进度

### 设计初衷

安装、回测、数据更新和标签计算各自写进度，界面要认多套字段。

### 设计背景

回测和标签还要保存错误、结果和机会列表，那些不是步骤计数。进度文件若塞进这些字段，就又变成业务文件。

### 解决方案

| 方案 | 做法摘要 | 优点 | 缺点 |
|------|----------|------|------|
| A：一份当前进度 | 只记步骤和子步骤 | 界面一条式子 | 不保留上一份任务 |
| B：每个任务一个文件 | 按任务种类分文件 | 可以同时看多份 | 界面继续分叉 |

### 决定

- **采用：** 方案 A
- **理由：** 界面只需要当前正在跑的那一次。错误和结果仍由各业务模块自己的记录保存。
- **影响：** 后开始的任务覆盖前一份进度。
- **后续：** 设计点 2 改为一个根节点一份文件。本决定不再使用。

## 设计点 2：同一种节点，按 id 查找

### 设计初衷

多个任务会同时跑。步骤还有步骤。调用方不应该声明节点在第几层。

### 设计背景

平铺的 step / sub 表达不了安装里面的导入，也表达不了数据源里面的页。两套文件格式会让解析器分叉。

### 解决方案

| 方案 | 做法摘要 | 优点 | 缺点 |
|------|----------|------|------|
| A：同一种节点嵌套 | steps 里只放进度节点，按 id 递归查找 | 格式统一，可以多层 | id 必须唯一 |
| B：步骤用另一种结构 | 根和步骤字段不同 | 根文件更短 | 扩展时要改两处 |

### 决定

- **采用：** 方案 A
- **理由：** 加字段时只改一种节点。tick 只带 id。
- **影响：** 有子节点的 ratio 来自子节点的 weight；叶子才用 done / total。

## 设计点 3：写盘可以合并

### 设计初衷

热路径上每个计数都立刻替换文件，没有必要。解析器按秒甚至更慢轮询。

### 设计背景

进度数字只在外部调用 tick 时改变。进程内需要立刻读到刚写入的数，磁盘可以晚一点。

### 解决方案

| 方案 | 做法摘要 | 优点 | 缺点 |
|------|----------|------|------|
| A：合并后写盘 | 连续 tick 先改内存，再把最后一版写入 | 读接口即时，写盘更少 | 进程突然退出会丢掉还没刷出的一次 |
| B：每次 tick 都替换文件 | 调用返回时磁盘已是新的 | 崩溃也停在最后一次 | 热路径写盘更勤 |

### 决定

- **采用：** 方案 A
- **理由：** 解析器不需要每一次 tick 都已经在磁盘上。日志仍在调用当次打印。
- **影响：** 没有定时器去推进进度。
