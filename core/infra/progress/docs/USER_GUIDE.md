# Progress — 用户指南

**版本：** `0.2.0`

进度统一写进文件——长任务把进度写到 JSON，前端和 CLI 都从这里读。  
相关：[README.md](../README.md) · [API.md](../API.md) · [ARCHITECTURE.md](./ARCHITECTURE.md)

---

## 功能总览

- 长任务跑起来后，进度统一写到 userspace 临时目录下的一份 JSON 里，谁想看谁来读
- 支持多层步骤——比如"先下载、再处理、最后保存"，每一层都有自己的进度
- 前端 BFF、命令行、安装脚本读的都是同一份文件，不会各说各话
- 连续多次刷新进度会合并写盘，磁盘不会被刷爆

## 配置说明

无用户可配项。进度文件的存放位置由系统统一管理，普通用户不需要动。

## 常见使用方式

### 场景 1：前端读进度

1. 在 UI 上发起一个长任务（扫描、回测、更新数据等）
2. 前端会周期性地去读对应的进度 JSON
3. 界面上就能看到百分比、当前在跑哪一步、还剩多少

### 场景 2：CLI 打印进度

1. 在终端里跑一个长命令
2. CLI 边跑边去读进度文件，把百分比打出来
3. 命令跑完，进度也跟着到 100%

## 常见坑与注意事项

- **进度文件残留导致一直显示 100%：** 上次任务异常退出，进度文件可能留在原地没被清掉。重启一下任务或删掉 userspace 临时目录里的旧进度文件即可。
- **多层任务 id 写错了读不到：** 子步骤的 id 是 `父id:子id` 这种格式，写错了就读不到对应那一份。
- **进度到 99% 卡住不动：** 多半是最后一步在收尾写库，再等等；长时间不动就看日志。
