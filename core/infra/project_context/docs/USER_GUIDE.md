# Project Context — 用户指南

**版本：** `0.2.0`

项目路径和配置的统一入口——找 userspace 在哪、合并默认配置和用户覆盖。  
相关：[README.md](../README.md) · [API.md](../API.md) · [ARCHITECTURE.md](./ARCHITECTURE.md)

---

## 功能总览

- 管 NTQ 跑起来的所有关键路径：项目根、userspace、策略目录、缓存目录
- 把 core 里的默认配置和 userspace 里的用户覆盖合成一份给模块用
- 给所有模块一个统一的"我在哪、我的文件放哪"的答案

## 配置说明

这个模块本身没有用户开关，但它是你"改配置"的入口。想调某个模块的参数，去 userspace 下放一份同名配置文件即可，系统会自动合并。

| 配项 | 在哪配 | 默认值 | 说明 |
|------|--------|--------|------|
| 各模块配置 | `userspace/` 下对应目录 | core 内默认 | 放同名文件即覆盖 |

## 常见使用方式

### 场景 1：找 userspace 在哪

1. 一般情况下 userspace 在项目根的 `userspace/` 目录
2. 如果安装时用过 `--userspace` 自定义了路径，会记录在 `.ntq/userspace-path.json` 里
3. 模块内部都从这里拿，不用你自己拼

### 场景 2：改某个模块的配置

1. 找到 core 里那个模块的默认配置文件
2. 在 userspace 对应目录下放一份同名文件，只写你要改的字段
3. 重启后系统会把默认值和你的覆盖合起来生效

## 常见坑与注意事项

- **直接改 core 里的默认配置会被升级覆盖：** 想长期生效，请把改动写到 userspace，不要动 core 的源文件。
- **改了配置没生效：** 多半是文件名或目录位置不对，对照默认配置的路径放。
- **userspace 路径里有空格或中文：** 引用时记得加引号，否则脚本会把路径切断。
