# Trace — 用户指南

**模块：** `infra.trace` · **版本：** `0.1.4`

**最低支持核心版本：** `>=0.5.0`

匿名 usage 上报——默认关闭，用户同意才上报，去敏感化后静默发送。  
相关：[README.md](../README.md) · [API.md](../API.md) · [ARCHITECTURE.md](./ARCHITECTURE.md)

---

## 功能总览

- 默认完全关闭，你不点头它就一条都不发
- 同意后也只做匿名上报——内容会先去敏感化（去掉栈帧、个人路径等），再静默发出去
- 发送失败不会打扰你，事件会进本地队列，等下次有网时再补发
- 上报的内容用来帮助维护者了解使用情况、统计错误

## 配置说明

| 配项 | 在哪配 | 默认值 | 说明 |
|------|--------|--------|------|
| `target_url` | `userspace/system/config/trace.json` | 官方收集地址 | 自定义上报目标 |
| `NTQ_TRACE_ENDPOINT` | 环境变量 | 空 | 不改代码临时覆盖上报地址 |

## 常见使用方式

### 场景 1：开启 / 关闭上报

1. 首次启动时系统会问你"是否同意匿名上报使用情况"
2. 同意就开，拒绝就关，之后不会再问
3. 想改主意就去 `userspace/system/config/trace.json` 改对应字段

### 场景 2：查看本机暂存队列

1. 没网时上报的事件会堆在本地队列里
2. 队列文件在 userspace 的 trace 目录下
3. 等网络恢复后，下次启动时会自动把积压的事件发出去

## 常见坑与注意事项

- **没同意过就不会发：** 哪怕队列里有东西，没拿到同意也一条都不会外传。
- **改主意后旧队列不会立刻清：** 关闭上报后，本地残留队列不再发送，但文件还在，可以手动删。
- **自定义上报地址只影响新事件：** 改 `target_url` 之前入队的事件还是会发去旧地址。
