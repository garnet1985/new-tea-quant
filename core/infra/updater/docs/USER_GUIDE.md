# Updater — 用户指南

**版本：** `0.1.0`

NTQ 升级流程编排——原地升级：替换源码、跑数据库迁移、收尾。  
相关：[README.md](../README.md) · [API.md](../API.md) · [ARCHITECTURE.md](./ARCHITECTURE.md)

---

## 功能总览

- 在你已经装好的 NTQ 上原地升级，不用重装
- 自动跑新版本的数据库迁移脚本，老数据不会丢
- 升级器自己会被拷贝到 userspace 里再执行，避免"边跑边换自己"的漂移问题

## 配置说明

无用户可配项。升级流程由 CLI 或 UI 触发，参数走默认。

## 常见使用方式

### 场景 1：CLI 触发升级

1. 拿到新版本的 NTQ 源码（git pull 或解压新包）
2. 在项目根跑 `python cli.py u`
3. 系统会先把升级器拷到 userspace，再从那里执行替换源码、跑迁移、收尾
4. 看到完成提示就可以正常启动了

### 场景 2：从 userspace 里的升级器启动

1. 直接跑 `python userspace/system/updater/run_apply.py`
2. 效果等同 CLI，常用于脚本化部署

## 常见坑与注意事项

- **升级中途断电：** 升级器会先拷贝到 userspace 再执行，避免执行到一半被替换掉；但断电仍可能让数据库迁移停在中间。重新跑一遍升级即可，迁移脚本是幂等的。
- **不要在升级过程中启动 NTQ：** 替换源码期间启动会读到不一致的代码。等升级跑完再启动。
- **不会自动检查新版本：** 这个模块只负责"拿到新包后怎么装"，不负责"网上有没有新包"。
