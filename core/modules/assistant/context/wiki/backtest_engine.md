# 回测调度

回测引擎只负责时间轴、任务分配、并行和资源监控。它不读业务表、不做买卖判断。策略枚举/价格因子，以及按股票跑的标签，都走这套调度。

怎么跑回测见 [运行回测](../know_how/run_backtest.md)。四步含义见 [回测四步](strategy/backtest_pipeline.md)。

## 两种执行模式

在策略 `simulation.execution.mode` 里选：

| 模式 | 逻辑 | 适用 |
| --- | --- | --- |
| `slice_based` | 按时间切片，每片处理全部股票 | 多股票、中等时间窗口 |
| `entity_based` | 按股票分组，每组独立跑完整时间线 | 少股票、长时间窗口 |

`slice_based` 的约束：有多少正式切片，至少加载多少次逐股数据。不要在任务开始时一次载入全窗口。

组合模拟不走这套并行调度，在主进程单线程完成。决策者是人机回放，也不走并行。

## 时间轴

默认按交易日推进，窗口来自回测起止日期，并受 `data.json` 系统边界约束。也可以显式传入日期点。

| 种类 | 说明 |
| --- | --- |
| `calendar` | 按交易日（默认） |
| `clock` | 按时钟（分钟级，期货用） |
| `event` | 按事件 |
| `custom` | 自定义时间点 |

## 运行时发生什么

1. 探测机器核数和内存
2. 规划批次或切片宽度
3. 并行执行：每个时间点回调策略/标签钩子
4. 监控内存和耗时，压力大时降低预加载

版本号、指纹、pin 不在调度层，见 [生效设置与指纹](effective_settings_fingerprint.md)。
