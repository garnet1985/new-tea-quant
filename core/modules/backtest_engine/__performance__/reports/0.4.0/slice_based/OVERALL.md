# 性能总览 — 按时间切片（slice）

- 生成时间: 2026-08-06T08:48:46Z
- BE: 0.4.0
- 模式: slice_based
- 模型: 墙钟 T ≈ T0 + k·N（N=股票数，交易日固定）

## 结论（先看这）

- **duckdb**: 吞吐随规模大致持平（首→末 +5%）：接近线性边际成本
- **mysql**: 样本档不足（至少 2 档）
- **pgsql**: 样本档不足（至少 2 档）

- 拟合: T ≈ 0.968 + 0.00928·N 秒
- 固定成本 T0: **0.968s**（在 N=2000 约占 5.0%）
- 边际成本 k: **9.28 ms/股**（含该股全部交易日）
- 近固定: 准备/规划 均值 0.0536s、极差 0.0164s → 像固定成本
- 近线性: 读数据+推进（每股票） 均值 0.0102s/股、极差 0.0014 → 像按股线性
- 样本翻倍附近（吞吐变化可为负）:
  - N500→N1000: 墙钟 2.19×（理想线性约 2.00×），吞吐 -8.8%
  - N1000→N2000: 墙钟 1.74×（理想线性约 2.00×），吞吐 +15.1%

## 怎么读

- 吞吐随 N **上升**：固定成本被摊薄（「越大越划算」）。
- 吞吐大致 **持平**：墙钟近似按股线性。
- 吞吐 **下降**：越大越慢，查调度/IO/内存/片宽。
- T0 是 sink（进程、规划、采样等）；占比随 N 变大应下降。
- entity 与 slice 分看，不要横比谁更快。
