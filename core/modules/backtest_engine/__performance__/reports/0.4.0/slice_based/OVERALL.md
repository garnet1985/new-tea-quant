# 性能总览 — 按时间切片（slice）

- 生成时间: 2026-08-07T06:30:23Z
- BE: 0.4.0
- 模式: slice_based
- 模型: 墙钟 T ≈ T0 + k·N（N=股票数，交易日固定）

## 结论（先看这）

- **duckdb**: 吞吐随规模大致持平（首→末 +5%）：接近线性边际成本
- **mysql**: 吞吐随规模大致持平（首→末 -0%）：接近线性边际成本
- **pgsql**: 越大吞吐越高（首→末 +17%）：固定成本被摊薄，或并行更吃得开

## 怎么读

- 吞吐随 N **上升**：固定成本被摊薄（「越大越划算」）。
- 吞吐大致 **持平**：墙钟近似按股线性。
- 吞吐 **下降**：越大越慢，查调度/IO/内存/片宽。
- T0 是 sink（进程、规划、采样等）；占比随 N 变大应下降。
- entity 与 slice 分看，不要横比谁更快。
