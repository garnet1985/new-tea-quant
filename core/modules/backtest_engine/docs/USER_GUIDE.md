# Backtest Engine — 用户指南

**模块：** `modules.backtest_engine` · **版本：** `0.2.1`

**最低支持核心版本：** `>=0.5.0`

`BacktestEngine 是回测调度引擎——把任务拆批次、按时间推进，自动管多进程和内存。`  
相关：[README.md](../README.md) · [API.md](../API.md) · [ARCHITECTURE.md](./ARCHITECTURE.md)

---

## 功能总览

- 把一大堆回测任务拆成小批次，按时间顺序一步步推进
- 自动探测机器 CPU 和内存，决定开几个并行进程
- 支持两种推进方式：按股票逐只跑（适合因子计算）、按时间切片跑（适合组合模拟）
- 跑的过程中实时监控内存压力，发现要爆就自动收缩
- 跑完返回统一结果：成功还是失败、完成多少个任务

## 配置说明

在哪配、配什么、默认值是什么：

| 配项 | 在哪配 | 默认值 | 说明 |
|------|--------|--------|------|
| 资源预算 | 引擎自动探测 | 按机器实际 CPU / 内存 | 不用手动调，它会根据机器情况自动决定开几个并行 |

用户层面没有需要手动调的字段——性能相关参数由策略 / Tag 侧统一规划。

## 常见使用方式

### 场景 1：上层模块跑一批因子

1. 策略或 Tag 模块准备好一批任务（一只股一个任务）
2. 指定起止日期和时间轴
3. 调用引擎入口，选“逐只跑”模式
4. 等结果返回，看完成多少个任务

### 场景 2：上层模块跑组合模拟

1. 准备好组合层面的任务清单
2. 指定起止日期和时间轴
3. 调用引擎入口，选“按时间切片”模式
4. 等结果返回，引擎会按切片一段段推进

### 场景 3：理解跑完后的返回结果

1. 跑完后拿到统一结果
2. 看 `success` 判断成功还是失败
3. 看 `mode` 确认这次用的是“逐只跑”还是“按时间切片”
4. 看 `completed_jobs` 数完成多少个任务

### 场景 4：让上层业务接管进度

1. 业务方提供“任务开始 / 每推进一天 / 任务结束”三类钩子
2. 引擎在每步触发对应钩子，业务方在钩子里做自己的计算
3. 引擎只负责调度，不替业务算账

## 常见坑与注意事项

- **别在没数据时还想跑空批次**：任务清单为空时它会直接成功返回，不会真的去算
- **不要绕过公开入口去摸内部实现**：引擎内部的批次规划、执行器、探针都不对外公开，跨模块直接 import 容易踩雷
- **想让它一次性吃掉所有日期**：按时间切片模式下禁止全窗一次加载，会按片推进，这是设计好的保护
- **进度条不显示不代表没在跑**：进度始终在算，只是是否打印到终端由上层控制
- **内存紧张时它会自动收缩**：看到并行度下降不用慌，是引擎在保护机器
