# Data Contract — 用户指南

**模块：** `modules.data_contract` · **版本：** `0.4.3`

**最低支持核心版本：** `>=0.5.0`

`DataContract 是声明式取数入口——你只写"我要 XX 数据"，它去搞定底层怎么查。`
相关：[README.md](../README.md) · [API.md](../API.md) · [ARCHITECTURE.md](./ARCHITECTURE.md)

---

## 功能总览

- 用一句"我要 XX 数据"取回结果，不用自己写 SQL、不用关心表名
- 内置一批常用数据键：股票 K 线（日 / 周 / 月）、股票列表、ST 区间、申万行业、宏观货币供应等
- 自动决定一次性取还是按时间切片取，回测跑长时间窗口不会一次把内存塞爆
- 支持"截至某一时刻"的取数方式，避免回测用到未来数据
- 你写的策略 / 标签脚本只需声明 key，框架自动注入对应数据

## 配置说明

无用户可配项。`data_contract` 本身不读任何 settings；它只在你声明 `DATA_KEY` 时去查 `data_manager` 里已落地的数据。

如果某个 key 取不到，通常不是这里的配置问题，而是底层表还没抓——去 `data_source` 把对应数据源跑一遍。

## 常见使用方式

### 场景 1：在策略里声明"我要日 K"

1. 在策略的 settings 里写 `data.requires`，列出 key（例如股票日 K）。
2. 框架启动回测时自动签发这份数据契约，按你设定的时间窗口取数。
3. 在策略逻辑里直接拿到的就是行级数据，不用管数据库。

### 场景 2：在分析脚本里临时取一段 K 线

1. 选定要查的数据键（例如股票日 K）。
2. 给出股票代码、起止日期。
3. 让契约立刻取数，拿到一个列表返回。

### 场景 3：避免回测用到未来数据

1. 在声明契约时，把时间窗口收敛到"当前回测日"。
2. 契约的时序机制会保证给你的数据不超过这一日。
3. 这样写出来的策略更贴近实盘。

### 场景 4：取申万行业、宏观等非 K 线数据

1. 选对应的 key（申万行业、货币供应量等都有现成 key）。
2. 不需要传股票代码的，直接签发即可。
3. 拿到的就是结构化列表，可直接喂给标签或下游分析。

## 常见坑与注意事项

- **"取不到数据"先看是否抓过：** 契约只是查本地库；如果底层表是空的，先去 `data_source` 跑 renew。
- **entity_ids 漏传：** 涉及"每只股票"的 key（K 线、ST 区间等）必须告诉它是哪只 / 哪些股票；全局类 key（交易日历、货币供应）则不要传。
- **改了 userspace 的契约代码不生效：** 进程内会缓存已发现的契约。改完后让契约系统重新扫一次（提供热重载入口），或重启进程。
- **K 线默认前复权：** 顶层 `open/close` 是前复权；要原始价就取行内的 `raw` 字段，要后复权就取 `hfq`。
