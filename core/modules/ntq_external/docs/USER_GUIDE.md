# NtqExternal — 用户指南

**版本：** `0.1.0`

`NtqExternal 是 NTQ 本地与官网的唯一对接点——查会员资料、走官网 AI 通道、提交反馈都从这里走。`  
相关：[README.md](../README.md) · [API.md](../API.md) · [ARCHITECTURE.md](./ARCHITECTURE.md)

---

## 功能总览

- 给应用内各处提供官网页面地址：免责声明、注册入口、用户协议、联系页、文档页
- 读会员资料：档位、猫粮余额、积分、是否 Pro、能不能用同步
- 走官网的会员 AI 通道——模型密钥留在官网，本机只持通用凭证
- 应用内提交评分和意见反馈
- 把使用 trace 上报到官网

## 配置说明

| 配项 | 在哪配 | 默认值 | 说明 |
|------|--------|--------|------|
| `base_url` | `userspace/system/config/membership.json` | `https://www.new-tea.cn` | 官网根地址；其它页面、AI、反馈、trace 地址都由它派生 |
| `NTQ_FEEDBACK_ENDPOINT` | 环境变量 | 由 `base_url` 派生 | 反馈上报地址的紧急覆盖口 |
| `NTQ_FEEDBACK_TIMEOUT` | 环境变量 | `3.0` 秒 | 反馈上报超时 |

其它配项（频控、提示概率等）属内部默认，普通用户不用动。

## 常见使用方式

### 场景 1：在应用里给"免责声明"加个跳转链接

1. 直接调用模块给地址的入口。
2. 拿回来的就是当前配置的官网免责声明页 URL。
3. 拼到 UI 的按钮上即可——别自己写死官网地址。

### 场景 2：展示用户会员档位

1. 确认用户已在本地完成会员登录、本地有通用凭证。
2. 调用读会员资料的入口。
3. 拿到归一化后的字段（档位、猫粮、积分、是否 Pro），直接渲染。

### 场景 3：让 Agent 走官网 AI 通道

1. 确认会员凭证存在。
2. 从模块拿 AI 通道的根地址和当前额度。
3. Agent 业务方按这个地址发请求，模型密钥不落地。

### 场景 4：在应用里加一个"提交反馈"入口

1. 收集用户输入的评分或文字。
2. 调反馈提交入口。
3. 看返回值：成功 `True`、失败 `False`——失败别打扰用户，静默即可。

## 常见坑与注意事项

- **没配置会员凭证时调用 AI / 查资料**：不会拿到真实数据，会归一化成"访客态"（reason=missing 或 rejected）。UI 要识别这种状态并提示去登录，别当成"接口挂了"。
- **断网或官网不可达**：不抛异常，也归到访客态（reason=unreachable）。和"未登录"是两种原因，提示文案要分开。
- **凭证不会出现在返回值里**：模块特意不往外发凭证。你自己日志里也别打印请求头。
- **反馈提交失败不会抛错**：只返回 `False`。别指望 try/except 抓住它。
- **本机回环地址会被强制改成 `127.0.0.1`**：开发时写 `localhost` 也会被改写，这是为了避免 IPv6 走 502，不是 bug。
