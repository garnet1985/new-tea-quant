## 2. 还没解决的问题

### 2.1 枚举 ROI 不是现金收益

`Investment._apply_exit` 仍是 `(exit_qfq − entry_qfq) / entry_qfq`，写入 `weighted_roi`。价格因子平均收益、胜负都吃这个数。

前复权是 `qfq = raw × 因子 + C`。`C` 来自后来的现金分红，旧 K 线可以被拽到 0 或负数。分母一坏，ROI 可以是 −250%、符号反转，**不是倒贴本金**。

止盈止损用 qfq 碰线（避免送转缺口被当成暴跌）——规则坐标仍可用。错的是把同一套百分比当成「这笔赚了多少钱」。

后复权（乘法 `hfq = raw × F`）能避开穿零；本仓库 **没有** 真正的 hfq（`adjust=hfq` 落到 raw）。即便有，`entry_raw × (1 + hfq_roi)` 也只是 `exit_raw × (F_卖 / F_买)` 的绕路写法，不是比「改股数 + 记现金分红」更本质。

### 2.2 资金层假设持有期内股数不变、不计红利

同一 `shares` 买、同一 `shares` 按 `exit_raw` 卖。持有期内 10 送 10 会少算一半卖出所得。现金分红不进账。没有公司行为事实时，这是**偏保守**的估算，有界、不反号。

### 2.3 不要静默分支

不要「qfq 分母为负就改 raw%」填进同一列 `weighted_roi`。那是换定义，平均数不可解释。qfq 坐标坏掉的笔：不计入前复权收益统计；钱看成本变化。

## 3. 下版目标算法（有分红送股事实之后）

数据：Tushare `dividend`（实测 2026-09-04，积分够、16 列都能拉到）。

只处理 `div_proc = 实施` 且 `ex_date` 非空。丢掉预案 / 股东大会通过 / 预披露（无除权日）。`ts_code + ex_date` **去重**（000001.SZ `20081031` 实施行会重复）。窗口外的未来实施日不要用。

登记日收盘仍持有才入账（登记日卖掉则无权；除息日再买也无权）。

**价差账户：** 只记 `股数 × raw` 进出。除息缺口留在这条路上（股价变低），不要再记一笔「除息收益」。送股 / 转增不进现金，只改股数：

```text
新股数 = 原股数 × (1 + stk_bo_rate + stk_co_rate)
```

实测 `stk_div == stk_bo_rate + stk_co_rate`（空当 0）。不要和 `stk_div` 加两遍。送股与转增对持仓效果相同。

**分红账户：** 只记税后现金（`cash_div`，不要 `cash_div_tax`）：

```text
现金 += 登记日股数 × cash_div
```

入账日用 `pay_date`（更接近到账）；缺则退 `ex_date`。`cash_div` 为 NaN 当 0。

**结算：**

```text
总资产 = 价差账户现金 + 分红账户现金 + 未平仓（当时股数 × 成本或市值）
真实 ROI = (卖出所得 + 持有期税后红利 − 买入花费) / 买入花费
```

卖出：`当时股数 × exit_raw`。不要再用任何复权 ROI 反推卖出价。

碰线继续 qfq；结算只认 raw 股数和红利现金。

### 3.1 仍不能当「全市场精确」

这张接口没有配股、增发、可转债转股、缩股。那些没有事实或没有「缴不缴款」规则之前，继续估算。

现有 `sys_adj_factor_events` 只有合成 `factor` + anchor，分不出分红 vs 送转，不能当双账户流水。
