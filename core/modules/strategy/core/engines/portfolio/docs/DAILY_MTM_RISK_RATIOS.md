# 资金层：按日盯市的夏普 / Sortino（未实现）

**状态：** 研究结论与算法草案。错误口径的夏普 / Sortino **已从代码和 UI 撤回**；正确实现另开专项，不要在 UI 调整分支落地。  
**位置：** `simulate` 成交已定之后、`finalize` 写报告之前；不改事件驱动模拟，不走 BE。

当前报告只保留 Calmar（区间总收益 / 最大回撤）。夏普 / Sortino 等日频盯市后再加。

---

## 1. 问题

业界年化夏普默认：每个交易日把组合按市价盯市 → 日收益（减无风险，本仓库第一版仍为 0）→ 均值 / 样本标准差 → ×√252。Sortino 同理，分母换成相对 0 的下行波动（上涨段贡献 0，分母用全部段数）。

当前资金层做不到这个口径。

### 1.1 模拟怎么记净值

`PortfolioSimulator` 按买卖事件走账户，换日时 `_append_equity` 调 `account.equity({})`。空行情字典下，持仓按 `average_cost` 计价。曲线只在成交换日记点，不是每个开市日。

图上的权益曲线还会再抽到最多约 80 点。标量回撤在抽稀前用全量事件点计算，但那些点仍是「事件日 + 成本价」。

### 1.2 不要用事件点去乘 √252

曾试用：

```text
r_t = (E_t - E_{t-1}) / E_{t-1}
夏普 = mean(r) / sample_std(r) × √252
Sortino = (mean(r) − 0) / sqrt(mean(min(r, 0)²)) × √252
```

无风险 / Sortino 目标收益均为 0。公式本身常见，但把事件段当成交易日去乘 √252 是**口径错误**，不是随机误差。该实现已删除。样本再多也不会收敛到日频盯市夏普。同一组稀疏点可以对应完全不同的真日频夏普（中间路径看不见）。

Calmar 仍是「区间总收益 / 最大回撤」，不是年化 Calmar。回撤来自同一条成本曲线，会一起被压低。

### 1.3 一个数量级例子

10 个交易日、真日频年化夏普约 2.3。只记下第 0、3、7、10 天四个点，仍乘 √252，得到约 5.7。四个端点相同、中间更抖或更平，真值可以是 ~0.9 或 ~6.2，四个点给出的永远是 5.7。

实盘观感（事件点夏普 6+、回撤 3%）不能拿去对「夏普 &gt; 3 要警惕」那张日频表。

## 2. 已排除的路

| 方案 | 结论 |
|------|------|
| 枚举给每笔机会算夏普，资金层当选择器去取 | 否。夏普属于**整份账户**，不是单笔机会。枚举无现金、无跳过、无仓位冲突。 |
| 枚举「完整路径」拼账户净值 | 否。落盘只有触发/买入/卖出等稀疏点，没有持仓期日序列。 |
| `price_change_rate_delta` 单独当输入 | 否。那是单股相对昨收的涨跌幅，不是账户收益。缺股数和现金权重。有收盘价即可，不必依赖该字段。 |
| 模拟改成按交易日 `Timeline.drive` / 再走 BE jobs | 否。成交逻辑不依赖每日市值；BE 是为全市场策略计算控 OOM 的。盯市只是给已成交持仓标价。 |
| 只改年化乘数（按事件间隔换 √N）、不盯市 | 否。数字会小一些，仍看不见持仓内波动，仍不是业界夏普。 |
| 周频盯市 | 可作降级，不能和日频公募比。第一版做日频。 |

SHIBOR 作无风险**合理**（库中已有 `sys_shibor`），但减年化 1.5%～2% 几乎拉不下来虚高的 6.x。第一版继续 rf = 0；接 SHIBOR 单独立项（建议隔夜，折成日利率）。不要用 LPR。

## 3. 约定实现：成交后盯市，再算风险比

资金模拟保持事件驱动（选仓、现金、上限、成交）。  
盯市是报告步骤：用**实际成交**（`sim.trades` / `trades.json`），不是枚举全表，也不是 `entity_list` 里出现过的代码。

```text
PortfolioSimulator.run（不变）
  → 盯市：成交 + 开市日 + 持仓期日收盘
  → 日净值序列
  → 现有 annualized_risk_ratios / 回撤 / Calmar / 曲线抽稀
  → ReportManager.finalize
```

同一条盯市曲线同时供给：**夏普、Sortino、最大回撤、回撤持续、Calmar、权益/回撤图**。只改夏普、回撤仍用成本价，总览会自相矛盾。

成交结果、钩子、测试不因盯市而变。库读失败只影响风险块（显示 — 或保留成本曲线并打日志），不要把模拟搞脏。

### 3.1 挂载点

建议：`PortfolioPipeline.simulate` 返回后、`finalize` 前；或 `ReportManager.finalize` 内、写 `equity_curve` / overall 之前。

`capital_metrics.EquityCurves.compute` 继续对「已按日排好的净值点」做派生指标。盯市函数负责产出按开市日排列的 `{date, cash, equity, open_positions}`，替换今天模拟器写出的事件点。

模拟器内部的 `equity({})` 成本记账可先不动（成交回放不需要市值）。有账户止损、按市值加减仓等**会改变成交**的规则时，再把盯市推进模拟循环。

## 4. 算法

输入：本次 `PortfolioSimResult.trades`、回测 `start_date`/`end_date`、`initial_capital`。  
输出：每个开市日的现金、净值、持仓数。

计价：仓位是未复权股数，盯市用**未复权日收盘**（`kline.load_raw` / `load_batch(..., adjust="none")` 的 `close`）。不要用前复权收盘去乘未复权股数。

### 4.1 回放持股与现金（不读行情）

按成交日期排序。每个开市日结束时：

- 现金：仅在买卖日因成交和费用变化；其余日沿用
- 各股股数：仅在该股买卖日变化
- 开市日列表：交易日历一次查询（回测期，市场与 `runtime_env.market_profile` 一致，A 股用 SSE 开市日即可）

回测结束仍持仓的，窗口接到 `end_date`（最后一个开市日）。

### 4.2 买卖当天

先按成交改现金和股数，再用**当日收盘**给**收盘后仍持有**的仓位标价。已清仓的股票当天不再计入市值（盈亏已进现金）。不要用全日涨跌幅去代替成交价。

### 4.3 非交易日（有持仓、无买卖）

```text
净值_d = 现金_d + Σ_i (股数_{i,d} × 收盘_{i,d})
```

停牌或缺 bar：该股沿用其最近一次已有收盘（昨收）。不要为填洞再拉更长历史。

空仓日：净值 = 现金，不读股票 K 线。

### 4.4 日收益与比率

对盯市后的 `equity[d]` 计算日收益后再年化：

```text
夏普 = mean(r) / sample_std(r) × √252
Sortino = mean(r) / sqrt(mean(min(r, 0)²)) × √252
```

无风险 / Sortino 目标 = 0。段数不足 2 或波动≈0 时不展示。相邻点必须是交易日，×√252 才成立。

最大回撤、回撤持续天数在这条全日序列上算（抽稀前）。写给 UI 的曲线仍可抽到约 80 点。

### 4.5 不纳入第一版

- 现金利息
- 盘中高低 / 用开盘价盯市
- 分红再投资与除权导致的股数变化（未复权股数 × 未复权收盘，缺口日按停牌规则）
- 无风险利率（SHIBOR）
- 价格层 / 枚举层夏普

## 5. K 线怎么取（内存与次数）

不要 `load_batch(所有成交过的股票, 整个回测区间)`。那会把空仓月份也灌进来，才是 OOM 点。

**需要行情的区间 = 该股买入日 → 卖出日（含当天）。** 清仓之后不再取。同一只股票两段互不重叠的交易，是两段窗口；一次 SQL 两个 `BETWEEN` 或两段隔得近时合成一段均可。

查询次数 ≈ **曾持有过的股票只数**（每只把窗口一次取完）+ **1 次交易日历**。不等于买入次数，也不等于枚举机会数。连续持有期间加仓仍是一段。

实现约束：

- 只取 `date + close`，不要整根 OHLC
- 按股或小批量（建议 10～20 只，对齐默认 `max_portfolio_size`），用完丢弃
- 峰值内存 ≈ 日净值数组 + 当前这一批收盘，不随「历史上滚过多少只」线性涨
- 累加：`净值[日] += 股数[日] × 收盘[日]`（现金序列先写好）

### 5.1 取数例子（2025 全年）

- 1–3 月持有 A、B；4 月加仓 C；5 月卖 A；6 月卖 C；B 拿到年底

三次 K 线 + 一次日历：

1. A：`20250101`～卖出日（约 `20250531`）
2. C：买入日～卖出日（约 `20250401`～`20250630`）
3. B：`20250101`～`20251231`
4. 日历：`20250101`～`20251231` 开市日

不要 12 次按月，也不要每个交易日打一次库。

## 6. IO 粗估（`rsi_v1_baseline` 仿真 3）

样本：500 只池、约 3 年（20230101～20260101）、最多 10 槽。

| | 枚举 | 资金成交 | 盯市（估） |
|--|------|----------|------------|
| 规模 | 1603 机会 / 347 只出信号 | 24 买、23 只真正买过 | 23 次 K 线量级（或 2 批） |
| K 线 | `stock.kline.daily` **11.55s**（全历史） | 模拟本身几乎不读 K | payload ~0.1s + 往返，合计 **0.3～0.5s** |

同比 5500 只 × 10 年：枚举机会可线性放到约 5.9 万；**盯市不跟着放**。满仓时收盘个数 ≈ 交易日 × 当天持仓数。

| 设定 | 大约收盘根数 | 估墙钟 |
|------|----------------|--------|
| 10 槽、10 年 | ~2.5 万 | **1～3 秒** |
| 100 槽、10 年 | ~25 万 | **10～30 秒**（约 10 倍，不是 100 倍，也不是 ×5500） |

慢的是全市场枚举。800 次串行小查询会把往返推到数十秒，用 10～20 只一批即可。不要为这件事上 BE。
