# 枚举层归因口径

**状态：** 口径已锁定（2026-10-02）。实现必须先对本文，对不上就停。总方向见 [ATTRIBUTION.md](./ATTRIBUTION.md)；战役格子 / 指纹见 [ATTRIBUTION_CAMPAIGN.md](./ATTRIBUTION_CAMPAIGN.md)。价格层、组合层另文。

**一句话：** 枚举归因看「策略探测到的全部机会」以及「每笔机会独立走完目标的纸面结局」；不去重、不算资金。

不定义 CLI / UI，不改指纹。

---

## 1. 产物

枚举留下两样，归因都要用，不要只用 `overall_report` 里四个汇总数。

- 探测到的全部机会（含同一标的时间重叠）
- 每笔机会按当时 `goal` 走完的结局：`exit_reason`、`weighted_roi`、`holding_days`、`completed_goals`

价格层会去掉重叠投资；组合层再受资金约束。那两层的账本不在本文。

报告必须有一句：**这是每笔机会独立走完目标的纸面结局，含重叠；不是价格层去重后的交易，也不是组合层资金。**

---

## 2. 回测者要问的

1. 找到的机会多不多、散不散？旋钮一动，数量和分布怎么变？
2. 这些机会的止损 / 止盈 / 过期合不合理？对哪类股票、哪段时期不合理？
3. 各道门在找机会时有没有干活？是放宽信号带来的机会多，还是某道过滤在砍？用户怀疑某因子没起作用时，必须能回答。

找机会的门要分清 **信号** 和 **过滤**。以 rsi_v3 为例：RSI 超卖是触发条件，PE 分位 / 净利同比是关了才跳过的过滤。

- 过滤贡献 = 关掉该门之后机会多了多少（覆盖、分布一起看）
- 信号贡献 = 阈值放宽 / 收紧之后机会怎么变

不要在「已经同时通过两道门的幸存者」上对 RSI 数值做 SHAP，再说「RSI 贡献了 68% 机会」——那是同义反复。

---

## 3. 可以归因（单次 version、现有产物就够）

### 3.1 找机会

- 数量：总数、覆盖票数 / 股票池、触发率、日均
- 股票分散：每股机会分桶、前 N 只占比；是不是少数票贡献大部分
- 两种时间分散必须分开报，禁止合成一个「分散度」：
  - 日历扎堆：按月 / 季的触发量
  - 每股间隔：同一只股票相邻两次触发的间隔均值 / cv（现有 `TimingDispersion`：均匀 / 中等聚集 / 较集中）
- 现有 `{vid}/enum/overall_report.json` 已有覆盖、每股机会分桶、每股间隔 cv，归因必须收；日历扎堆从实体明细补

### 3.2 目标结局（就放在枚举，不推到价格层）

- 按 `exit_reason`（止损 / 止盈 / 过期 / 期末等）的笔数、占比、均收益、持有天数
- 止损 / 止盈 / 过期是否集中在少数票、少数月份
- 高止损率的票 vs 高止盈率的票（先按数据分组；行业是后贴标签，不是第一刀）

### 3.3 止盈后面还有没有涨（有条件）

仅当设置**不是一档全平**时，同一次回测就能测：

1. **分档止盈：** 第一档不要 `close_invest` 全平，留仓碰更高档；看 `completed_goals` 各档打到没有。允许某档 `exit_ratio: 0` 作探测档。
2. **动态止盈：** 止盈档 `actions: ["set_dynamic_loss"]` 激活 `goal.dynamic_loss`（从高点回撤平剩余）。第一档卖一部分后剩余仓跟涨，最终收益对第一档的差就是后面那段。

当前 rsi_v3 是 +20% 一档且 `close_invest: True`。这种设置下同一次回测看不到后面。报告必须写明：要测后面，加分档或打开动态止盈，或 overlays 对照「全平」vs「分档 / 动态」。禁止在一档全平的结果上编「如果止盈更高会怎样」的百分比。

## 4. 需要对照格（或改 settings 再跑）

### 4.1 门有没有干活

overlays / matrix 已经在做减法，报告要把它说成过滤 / 信号贡献，不要只报账户收益。

- 有 / 无：`max_pe_percentile: None` vs 30。rsi_v3 例：RSI20+PE30 为 18 个机会，关掉 PE 为 32 个 → PE 大约砍掉一半 RSI 命中
- 阈值：RSI 20 vs 25（PE 仍开）为 18 vs 78 → 放宽信号比关掉 PE 多找出来的更多
- 交叉：matrix 的 2×2 看两道门一起动是相加还是打架
- 对照格必须同时动数量和分布：放宽 RSI 之后是更多票都有机会，还是还是那几只票连打几枪。只报机会总数算偏差

单次 version、没有「关该过滤」那一格时：落盘的都是各道门都过的，看不到拒绝了谁。只允许说「本格看不出该过滤有没有干活，请 overlays 写 `None`」。以后若 `has_opportunity` 记下失败原因，单次也能做漏斗；那是增强，不是第一刀成立条件。

### 4.2 仍须对照才能答的目标问题

- 过期是不是太短 / 没耐心：分档测的是涨幅梯子，不是持有天数。靠更长的 `expiration` 对照格，或过期时不要一次平完
- 波动大但止损太紧：靠放宽止损的对照格；没有格子只允许说「止损堆在这些票、这些月」

没有对照格时只做本章基准诊断，不要假装扫过参数。

---

## 5. 明确不做

- 用 SHAP / 分类器解释 `goal.stop_loss` 等旋钮常数
- 把枚举纸面 ROI 说成账户收益或价格层去重后的交易
- 在已经触发的样本上用 RSI / PE 数值解释「贡献了多少机会」（幸存者偏差；要用关过滤 / 改阈值的对照）
- 没有对照格时编反事实百分比
- 行业 Top5、牛熊、HHI 作为第一刀成立条件（可后加）
- 决策 / 实盘（`sd`）不进枚举归因
- 把重叠机会当成可以同时持有的真实仓位
- 把止盈 / 止损诊断挪到价格层当主答案（价格层只对照「去重后是否仍如此」）

---

## 6. 数据从哪读

- 汇总：`{vid}/enum/overall_report.json` 的覆盖、分桶、`TimingDispersion`
- 明细：`enum/entities/*.json` 的 `trigger_date`、`entity_id`、`exit_reason`、`weighted_roi`、`holding_days`、`completed_goals`
- 旋钮：各格 `effective_settings` / overlays / matrix，与战役同一套身份
- 不要为枚举归因去行情库猜出场后的路径；路径以枚举当时按 `goal` 走出的结果为准

---

## 7. 和价格层的边界

- 枚举：全部探测到的机会 + 各自目标路径
- 价格：去掉重叠之后，实际当成一笔价格投资的子集
- 若枚举止损率高、价格止损率低：被去重掉的可能是扎堆亏损机会。这句话留给价格层对照，枚举章只报枚举侧
