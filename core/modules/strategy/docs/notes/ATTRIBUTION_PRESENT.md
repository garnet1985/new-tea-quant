# 归因如何展示

**状态：** 口径已锁定（2026-10-02）。各层问什么见 [ATTRIBUTION.md](./ATTRIBUTION.md)；枚举 / 价格 / 组合口径另文。战役格子仍以 [ATTRIBUTION_CAMPAIGN.md](./ATTRIBUTION_CAMPAIGN.md) 为准。

**一句话：** 哪一层回测跑完，就出那一层的归因。一份报告三个区块：事实、结论、建议。不要等三层都跑完再出一份混叙事。

---

## 1. 为什么一层一份

调机会分布时，账户利用率和满槽漏单是噪音。`attribution.steps` 可以只写 `enumerate`；层内诊断跟回测层走，不要求价格、组合已经跑过。

- 枚举可单独出报告
- 价格对照合并偏需要枚举产物（回测已有依赖）
- 组合买到/漏掉需要价格账本；缺价格就写「本层答不了」，不编漏掉集合

战役仍是一次任务一个文件夹：对照的是**同一套层内指标**的差分。不是三个 `sa`。三层都跑齐时，总报告把已有层报告订在一起。

`Analyzer.run`（CLI `sz`，机会表切片 / SHAP）仍不自动挂在 simulate 上。层诊断是另一条入口：该层 Pipeline 结束后由 `Analyzer.layer` 写 `{vid}/{enum|price|portfolio}/attribution.json`。

机器学习不挡调试：枚举默认不做 XGB；价格附录可关。

---

## 2. 一份报告三块

同一文件、三个作者，不要拆成用户要找的两份。

| 区块 | 写什么 | 不写什么 |
|------|--------|----------|
| **事实** | 统计（及可选 ML）数字：数量、分散、出场、胜率、买到/漏掉 | 解释、下一步、反事实百分比 |
| **结论** | 这些数字说明什么（偏少、较集中、止损偏多、门本格看不出） | 「如果改 X 年化 +2%」 |
| **建议** | 下一步改哪一类设置；有 overlays 就引用格子上的同一套指标 | 只跑枚举时建议资金；无对照格时编百分比 |

只跑枚举：建议里不准写槽位 / 利用率。结论可以点名「要看门贡献请 overlays」。

---

## 3. 改造顺序

先枚举（已接），再价格（已接），再组合（已接 `Analyzer.layer`），最后战役对照改用同一套层内指标。
