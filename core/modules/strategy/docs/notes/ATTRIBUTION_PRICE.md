# 价格层归因口径

**状态：** 口径修订（2026-10-03）。回放引擎见 [PRICE_REPLAY.md](./PRICE_REPLAY.md)。战役入口 CLI `spa`（须先 `sp`）。总方向 [ATTRIBUTION.md](./ATTRIBUTION.md)；枚举 [ATTRIBUTION_ENUM.md](./ATTRIBUTION_ENUM.md)。**副本与管道**以 [ATTRIBUTION_CAMPAIGN.md](./ATTRIBUTION_CAMPAIGN.md) §0 为准；自变量 [ATTRIBUTION_INPUTS.md](./ATTRIBUTION_INPUTS.md)。

**一句话：** 价格层在枚举机会上去近邻，留下代表机会并沿用该副本已定目标路径走完（可并行、不锁仓）。回答：去噪后等权投一笔，整体能不能赚、赚得够不够；共用「如果」副本上这些指标怎么变。

---

## 1. 去近邻重复是什么（不是合成一笔）

枚举会输出全部命中，含同一段信号连打的枪。若全部拿去算胜率，同一段行情会被算很多次，结论没有说服力。

价格层要做的是：

- 同一标的上，若后一笔与前一笔在 base 轴上的间隔 **≤ `opportunity_merge_gap`**，则**不投后一笔**，只保留这一组里**最早**的那一笔作代表。
- 间隔拉开、不再算同一组之后，才允许再投下一笔。
- **不是**把多笔合成一笔新路径；**不是**锁仓（持仓未平仍可因间隔够远而留下另一笔；同股互斥在组合层）。
- 代表机会的进场 / 止盈 / 止损 / ROI **沿用该副本枚举当时的完整生命周期**，价格层不再另配一套止盈止损。

引擎细节与钩子 `is_new_opportunity` 见 [PRICE_REPLAY.md](./PRICE_REPLAY.md)。涨跌停 / 停牌买不进仍由引擎处理。

去噪规则本身是引擎职责；归因层**不把**「如何去噪 / gap 取多少」当作主问题。`opportunity_merge_gap` 只是可选的共用「如果」轴。

---

## 2. 用户为什么要跑这一层

1. **去噪后的代表机会有没有边、赚得够不够。** 胜率、平均 ROI、盈亏比、总盈亏 / ROI 分布。枚举纸面含密集成片，不能当这个答案。想象：无穷资金、每个非噪音机会投一股。
2. **留下的样本能不能代表普遍现象。** 利润是否堆在少数笔 / 少数票；按年 / 季边是否垮。
3. **共用「如果」在价格账上的结局。** 因子 / 止损止盈等已在战役展格里的轴，在各副本的价格产物上，胜率与均收益等如何相对原版变化（身份与 `sea` 相同，只是此时才补价格产物）。
4. **给组合层当对照。** 价格有边、账户没有 → 去查资金；价格没边 → 先改想法，不是先改仓位。

---

## 3. 用户想了解什么

1. **整体有没有边。** 胜率、均收益、盈亏比；完成笔数、总盈亏（已有则应收进报告）。
2. **是不是靠少数几笔撑的。** 去掉赚得最多的几笔 / 几只票，平均 ROI 还正不正。
3. **钱从哪种出场来。** 止盈 / 止损 / 到期各自贡献了多少利润（描述结构；**不是**替用户定义盈利区间）。
4. **边会不会随时间垮。** 按年 / 季切；跨窗口仍走 `sw`。
5. **（可选）** 间隔阈值若在共用展格里，边与结实程度怎么变——降级为可选项，不是本层主轴。
6. **附录：** 这些代表成交上，现场因子还分得出赚亏吗（分桶 / SHAP）。不要讲成「RSI 贡献了多少机会」。

枚举已经回答、这里不要展开：机会散不散、门有没有干活、止盈止损按票/按月是否合理（那些是枚举纸面诊断）。  
**不做：** 用 MFE/MAE 或特殊探针代算「盈利空间」——空间由用户配置止盈止损；若将来做固定探针，另案，不进本层主问题。

---

## 4. 可以归因

单次 version 就能做：

- 账本：完成笔数、胜率、平均 ROI、盈亏比、总盈亏、ROI 分位 / 分桶（price `overall_report` 已有，必须收）
- 利润是否头部化：前 N 笔 / 前 N 只票贡献占比（分母宜用盈亏绝对值之和，避免净利润对冲虚高）；去掉它们之后均收益还正不正
- 出场对总利润的贡献：各 `exit_reason` 的笔数、均收益、利润合计
- 按年 / 季的胜率与均收益
- 相对枚举：笔数差（近邻跳过 + 涨跌停 / 停牌）可作一句范围说明；**不做**「跳过的 vs 留下的」盈亏对比

有对照格时：对照的是上述账本指标，格子来自**战役共用副本**（与 `sea` / `soa` 同一套身份），不是 `price_factor.inputs` 私有展格。

现场因子分桶 / SHAP：附录，且只用这本账的成交。

---

## 5. 明确不做

- 再做一遍机会分散、门的有/无、止盈止损按票/按月诊断（那是枚举的）
- 另起一套「只属于价格层」的副本身份（与 CAMPAIGN §0 相悖）
- 把「如何去噪 / gap 是否合理」当本层主问题
- 系统代算盈利区间（MFE/MAE 等）；用户通过配置止盈止损表达空间
- 对比「因间隔被跳过的机会」与「留下的代表机会」谁质量更好
- 把价格层 SHAP 当这一层的主答案
- 把价格层 ROI 说成账户收益
- 用锁仓解释「为什么某笔没进价格账」
- 因为笔数和枚举一样，就整章省略

---

## 6. 与共用 `inputs` 的关系

- 价格归因**不**单独拥有对照轴集合；轴在战役共用展格里（见 INPUTS §0 / §3）。
- 副本改了 `goal.*` / `core.*` 时：`spa` 读的是该身份补齐后的**价格**产物，与枚举纸面故事分开陈述。
- `opportunity_merge_gap`：可选共用轴；未声明时不必为价格层强行默认扫 gap。
- 已删除旧规则「`spa` 校验拒绝 `goal.*` / `core.*`」——那是私有格子模型。

---

## 7. 和组合层的边界

价格层：去近邻后的等权代表样本、可并行、不受组合资金 / 持仓上限限制。  
组合层：这本账里实际买了哪些；同股账户已持仓则跳过。口径见 [ATTRIBUTION_PORTFOLIO.md](./ATTRIBUTION_PORTFOLIO.md)。  
两层对照的 version 集合相同；`soa` 只是此时才补组合产物。
