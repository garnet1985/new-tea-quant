# 决策者模式：资金回测回放

**状态：** 口径已锁定（2026-09-12）。会话引擎 + CLI REPL（`sd` / `sdl` / `sdd`）+ 走完 `finalize` 已落地。BFF D1 已挂（`/api/v1/strategy/.../decision/sessions`）；FED 未做。  
**一句话：** 决策者模式是 **当前策略** 的 `portfolio` 回放。用户唯一能改的是 **选谁**（`on_pick_portfolio_member`）和 **买多少股**；其余全部沿用资金回测。  
**位置：** NTQ 第四层；与 enumerate / price_factor / portfolio 同一 version。代码在 `core/engines/decision_maker/`。

---

## 1. 目标

仍是在回测 **这一份策略**，不是另开一套交易游戏。改目标、算法、数据、资金约束，就是另一份策略。

行为上对齐用户日常用 NTQ：扫描出机会 → 自己抉择 → **严格遵守纪律**（决策者模式 **假设并强制** 守纪律）。

要让用户：

- 身临其境，承受回撤
- 自己选仓，体会选择的分量
- 走完后对照机器资金报告，看主观抉择是否普遍更好
- 按纪律把「扫描 → 交易」走完，感受实盘用法

---

## 2. 和资金回测的关系

机器 `portfolio`：

```text
enum 机会 → 入场事件
  → on_pick_portfolio_member / EntrySelector（选谁）
  → AllocationStrategy（买多少）
  → 现金 / 手数 / 流动性 / 组合上限（硬约束）
  → 成交、止盈止损 / 到期（纪律）
  → 日频盯市报告
```

决策者：**同一条管道**。人坐在选谁、买多少两个旋钮上。

| 谁决定 | 机器 | 决策者 |
|--------|------|--------|
| 机会从哪来 | 枚举结果 | 同一份枚举 |
| 选谁进组合 | `on_pick_portfolio_member`，未 override 则 `EntrySelector` | **用户**（等价于当场 override 该钩子） |
| 买多少股 | `AllocationStrategy`（equal_capital / equal_shares / kelly） | **用户提出股数** |
| 成交价、费用 | 策略 / 资金层 | 不变 |
| 现金、手数、流动性、`max_portfolio_size` | 硬约束 | **同一把硬尺**，超了下不成 |
| 入场之后 | 止盈止损 / 到期，不可中途买卖 | **不可干预** |
| 报告 | 日频盯市曲线 + 夏普 / Sortino / 回撤 / Calmar 等 | **同结构**；走完与机器 portfolio 对照 |

钩子现状：`on_pick_portfolio_member` **不返回 sizing**。决策者不是改这个返回值形状，而是人同时承担「选谁」和「买多少」两步；股数仍过资金层同一套硬约束。

## 3. 锁死的规则

### 3.1 策略冻结

会话绑定当前策略、当前 version、当前 `settings`。目标、算法、数据、费用、流动性、组合上限、回测区间都不能在局中改。

### 3.2 主观只发生在入场

用户决定：这笔枚举机会买不买、买几股。界面按市场手数步进，并显示约等于多少钱。  
一旦买下：不可提前卖、不可扛过止损、不可加仓、不可减仓。之后只等纪律事件。

不买也是抉择。昨天那条枚举没买就过号；今天枚举又扫出一条，那是新抉择（按枚举行为单位，不是按股票名锁死一次）。

### 3.3 时钟：类似足球经理游戏的推进模式

交易日历 **一天一天推进**。界面 **只在有 event 的日子暂停**。

| event | 用户 |
|-------|------|
| 当日枚举出现需要抉择的机会 | **核心操作**：选谁、买多少（可全部不买） |
| 持仓触发止盈 / 止损 / 到期 | **只读通报**，不能改 |

无 event 的日子（含休市）**直接跳过**。用户看到的永远是有事的那天：新机会，或持仓触发目标。中间那几天的逐日浮盈浮亏 **不展示、也不必知道**。现场只给 **当前这一停** 的现金和 `holdings`（点开才查当日收盘）。**完整日频曲线不在 `next` 里累加**，等走完后按成交回溯，与 portfolio 同一套 `finalize`。

`next`（命令行与 UI）推到下一个**事件日**：纪律出场（仓位变化）或新机会，或整段结束。只出场、没有新机会的日子也停，只读通报；空 `done` 后再 `next`。

同一天既有纪律出场又有新机会：先结算出场（只读），再出示当日新机会。这是资金回放顺序，不是让用户先看到未来再选。

### 3.4 硬约束不破例

现金不够、持仓已满、手数 / 流动性限制、组合上限：下不成就是下不成。  
用户觉得不合理，是策略的痛点，拿去改策略；不是让他在决策者里破例。破了就不是身临其境。

### 3.5 现场信息：当前暂停日之前

推进到日期 \(D\)（例如 2025-06-04），用户决策能看到的数据都不能越过 \(D\)：

- K 线 / 指标：窗口右端是 **\(D\) 当日**（含当日 bar），不含 \(D\) 之后。命令行 `info` 看过去 N 根表，不画图，见 §8
- 胜率、平均 ROI：机会列表按 **该标的**、`exit_date < D` 的已完成枚举（须已进场且持仓已归零；没有样本则 —）；`info` 另给整份策略 as-of。不是全周期，不含本笔未来
- 本局已发生的账户状态：现金、持仓；`holdings` 上的浮动盈亏是 **这一停** 的快照，不是中间空日的日记。完整净值 / 回撤曲线只在终局报告

**不给：**

- \(D\) 及之后的 K 线 / 指标 / 成交
- **本笔**未来的卖出日、出场价、本笔盈亏
- 机器当天选了谁、整段机器 portfolio 终局数字（走完再对照）

枚举落盘若已带出场结果，展示时必须裁到 as-of。这与以后 scan 的默认 adapter 同一把尺：调回测历史，告知当前机会的历史成绩，历史停在 as-of。

### 3.6 终局对照

决策者走完，用本局 `trades` 走和 portfolio **同一套** `ReportManager.finalize`：按持仓窗口回查 hfq 收盘、隔夜 SHIBOR，写出日频盯市曲线、夏普 / Sortino / 回撤 / Calmar、最终总资产、总收益率。不是推进时逐日把净值写入存档。未走完区间 **不出** 这份报告。

再和该 version 已有的机器 `portfolio/` **并排对照**（两份同结构报告）。不另写第三份 diff 文件。决策者 **只依赖 enum** 就能玩；建议先跑完 portfolio，这样有参照物。机器还没跑：仍可玩，只是没有对照物。不另做一套决策者指标。

默认进哪份 version：与 `so` 相同，当前 `settings.py` 命中的 vid。要打旧号显式带 version。

旧决策者会话不回填；改策略或重跑上游步按 version 规则作废下游。

## 5. 会话与存档

- 一次决策者 = 一个 **session id**，map **一份**回测 version。同一 version 可以开多局（再打一局 = 新 id）。
- **不要覆盖上一局。** 走完再开 = 新 `{dm_id}`，旧目录留下对照。中途 `quit` / Ctrl+C 再进 = **续同一局**（写回该 id 的存档，不是新号）。
- **未完成也可以再开新局。** 旧的未完成局照留。命令行怎么选见 §6。
- 想丢掉某局：显式删除，不要靠覆盖。中途存档，进程退出（含 Ctrl+C）必须先写存档。
- 存档两层：**游标**（已提交的日期、账户、成交）和 **当天草稿**（还没确认的 picks）。
- **时间不能倒退。** 只有 `next` 会提交当天并往前走；提交后这一天冻结。想重来只能新开 session。`next` 之前可以改草稿、可以 `reset` 整单重录。
- 上游枚举作废：会话停在旧 version，不偷偷跟到新号。

引擎动作（UI / CLI / 测试共用）：`start` → 停在事件日 → 改草稿（仅有机会时）→ `done` 看账单 → `next` 提交并推进（或 `reset` 重录）→ 区间结束出与 portfolio 同结构的报告。

## 6. 命令行：SQL 模式

用户 CLI 进一个单独 REPL（类似数据库 sql 模式），不是 `se/sp/so` 那种一次跑完，也不是每步新开一条进程。`python cli.py s` **不**自动开决策者。

进 REPL 时绑 **当前 `settings.py` 命中的 vid**（与 `so` 相同）。该 vid 下必须已有 enum；没有则拒绝进入。portfolio 不强制，建议已跑完以便对照。

| 未完成局 | 默认 `sd` |
|----------|-----------|
| 0 | 新开一局 |
| 1 | 续那一局 |
| ≥2 | **不猜**。列出 id / 停在哪一天 / 是否完成，要求带 `{dm_id}` |

显式新开（`--new` 一类）无论有几局未完成都分配新 id。显式带 id 则进那一局（已完成的只能看报告，不能再 `next`）。

管理命令要有，对齐 `sdv`：

| 动作 | 作用 |
|------|------|
| 列出 | 该 version 下各 `{dm_id}`：进行中 / 已完成、当前日 |
| 删除 | 删掉指定 `{dm_id}/`，不可恢复。未完成、已完成都能删 |
| 进局 | 默认按上表；或指定 id；或强制新开 |

删整个 `{vid}/` 时这些局一起走，不必再单独级联。

提示符始终带当前日、现金、持仓。`quit` / Ctrl+C：存档并离开会话，再进按上表续。

当日机会用 **当天编号** `[1]` `[2]`…，输入 `<编号>:<股数>`，不用在命令里敲完整代码。

两种状态：

**录入中** — 可输入编号:股数，或 `done`。

```text
发现了新的机会！
  [1] 000001.SZ 平安银行  买入价: 10.52  历史胜率: 62%  平均ROI: +8.5%
  [2] 600036.SH 招商银行  买入价: 32.15  历史胜率: 58%  平均ROI: +7.2%

输入 <编号>:<股数> 添加选择，或输入 done 确认
> 1:1000
✓ 已选择: [1] 平安银行  1000 股  约 10,520 元
```

同一编号再输入则覆盖。非法（编号不存在、股数不合法、现金/上限/手数不够）当场报错，其余草稿不动。「约 xx 元」= 股数 × 买入价（未含费）；真扣现金在 `next` 时按资金层费用算，超了则仍停在当天并报错。

**账单中**（刚 `done`）— 改单只能 `next` 或 `reset`；下面查询命令随时可用。

```text
> done

当前选择:
  [1] 平安银行  1000 股  约 10,520 元
  [2] 招商银行  500 股  约 16,075 元
  合计: 26,595 元  (现金: 852,340 元)

请输入 next 继续推进，或 reset 重新下单
```

| 输入 | 作用 |
|------|------|
| `next` | 提交当天（空选择 = 本日不买）并往前走。跳过无 event 日；停在下一事件日（仓位变化或新机会），或整段结束。 |
| `reset` | 清空草稿，回到录入中，日期不变。 |
| `holdings` | 持仓明细：每只浮动盈亏、持有天数、**策略声明的**止盈/止损价位或比例。不是这笔未来哪天触发。`status`、`holding` 是同一条命令的别名。 |
| `info <编号|代码> [N] [字段,...]` | 截至 \(D\) 的最近 **N 根开市日** 数值表（K 线 + 指标），不画图。语法见 §8。 |
| `help` | 命令列表。 |
| `quit` / Ctrl+C | 存档并退出 REPL。再进从游标续。 |

没有 `yes`。`done` 是看账单，`next` 才是真正提交。Ctrl+C 时若还在账单中，存档草稿、下次仍停在这一天（可再 `done`）。没有 `back` / `undo`。

止盈止损在 `holdings` / `info` 里只给**规则价位**（策略 goal），不给本笔未来卖出日。K 线与指标同样停在 \(D\) 之前。

## 7. 推进：枚举事件 + 持仓盯市

推进 **简单，但不是只跳枚举日期**。

资金层已经把 `EnumResult` 展成 `PortfolioEvent`：有合法 `entry_price_raw` 才生成 **一买**（`entry_date`）+ **按 `completed_goals` 的卖**（没有切片则仍用 `exit_date` 一卖）。无 `entry_date` 的行不进决策者。抉择日 = **买入日**（`entry_date`），与机器 buy 事件同一天，不是扫描日 `trigger_date`。

同一标的同一买入日若枚举叠了两笔（常见于 entity 枚举在未成交前又扫到信号），决策者只出示 **第一笔**，与资金层 `EntrySelector` 跳过已见 entity 一致。已持仓的标的不再作为新机会暂停。

`completed_goals` 有分档日期和名称，用来写只读日志里「完成了哪个目标」，也是资金层多次卖出的数据源。**一笔交易在持仓归零后才完结**（胜率 / ROI 此时才有）。流动性卖不完时，枚举在后续每个时间周期继续卖，直到 100%。资金层按这些切片兑现真实股数，不再二次按当日量 clip。

`next` 时：

1. 提交当天草稿（选谁、股数；空选择 = 本日不买）
2. 跳到下一个 event（新机会或持仓出场）；空日不打印、也不在存档里记逐日净值
3. 持仓碰到目标卖出：只读通报（原因 / 目标名 / 盈亏），钱按资金层规则，**当天停钟**
4. 有新 `entry_date` 则同时出示机会；没有则只读出场。区间结束则对 `trades` 做 portfolio 同款 `finalize`（回溯持仓窗行情 + SHIBOR）

引擎可以用完整 `EnumResult`（含未来出场）来排程；展示给用户时仍裁到 \(D\) 之前。`to_opportunity()` 已经屏蔽了 result / ROI。选仓过滤与资金层 `build_events` 相同（含 `should_skip_enter`）。

## 8. `info` / 点开：懒加载，不预热全市场

持仓浮动盈亏（`holdings`）只在用户查看时查 **当前持有的那几只** 的当日收盘，跟 `max_portfolio_size` 同量级，不算 `info`。终局曲线不靠这个缓存。

K 线窗口和现场算指标：**只有** `info` / UI 点开才查库。不要在每个抉择日预拉全部机会。

命令行 **保留 `info`**，不画图。窗口是「停在 \(D\)、往回 N 根开市日」，不是只打今天一行，也不是把回测起点到 \(D\) 全倒出来。

```text
info 1              → 默认 N=60，列 = date + OHLCV + 策略声明的全部指标
info 1 120          → 最近 120 根
info 1 close,rsi    → 默认 N，只保留这些列（date 永远在）
info 1 120 close,rsi
info 000001.SZ 60
```

第二段若全是数字则是 N，否则当字段白名单（逗号分隔）。N 默认 **60**，上限 **252**（约一年），且不能越过 \(D\)。只要 keep 列表，不要 drop 列表。表上方仍打 as-of 胜率 / 平均 ROI（全策略；可附该标的）。

图画、交互缩放只在 UI。

缓存：小 LRU（大约 **16 只**），key = 股票。`next` 之后丢掉「当前既未持仓、也不是刚点开」的条目；持仓可留、按新的 \(D\) 补 bar。会话存档 **不写** K 线。日线量很小，16 只不会撑内存；真正贵的是乱算指标，所以用条数上限而不是再上复杂权重。

## 9. 磁盘布局

挂在**现有仿真 version 下面**，不要另起 `results/decision_making/{strategy}/...`（策略目录已经是根；三步已经在 `simulations/{vid}/`）。

```text
{strategy}/results/simulations/{vid}/
  enum/ | price/ | portfolio/
  decision/
    meta.json          # next_session_id + 本 version 下各局索引
    {dm_id}/           # 1, 2, 3… 同一 version 可多局
      session.json     # 游标、账户、当天草稿
      …                # 走完后的报告（与 portfolio 同结构）
```

目录名用 `decision`，与 `enum` / `price` / `portfolio` 同级短名。`{dm_id}` 按该 version 自增，不是全局 UUID。

删掉 `{vid}/`（`sdv`、上游作废清下游）时，这些局一起走。机会列表仍读该 version 的 `enum/`，不必在 session 里再存一份枚举。

## 10. 实现备忘（第一刀已定）

命令行短别名：`sd` 进 REPL，`sdl` 列出，`sdd` 删除。新开用 `--new-session`（全局 `-n` 仍是从模板建策略）。指定局用 `--session`，旧 version 用 `--version`。

用户股数不走 `AllocationStrategy.calculate_shares_to_buy`，只过 `floor_shares` / `apply_participation` / 费用 / 现金 / `max_portfolio_size`。建议买入则按 `allocation.mode` 走同一套公式：等股给手数、等价给槽位资金对应股数、凯莉给凯莉仓位，并标明根据。

UI 屏幕、scan adapter 仍后做。BFF 决策者路由：`core/bff/docs/routes/strategy.md` D1。
