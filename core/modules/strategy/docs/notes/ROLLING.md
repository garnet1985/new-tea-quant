# 滚动对照（2026-10-08）

**状态：** 产品口径已锁定。实现仍是旧的「窗口互相比、选出收益最好的一段」，不要当已完成功能。

**一句话：** 资金回测跑完之后，用户另配若干区间，用当前同一套设置再跑，报告只给出每段相对这次回测的差值。过拟合、时效、稳不稳定由用户自己看。

---

## 1. 它不是什么

- 不是归因。归因回答「在这次回测的区间里，改一个设置，结果变好还是变坏」。Rolling 不再放在 `attribution.py`，不和参数战役同一张表，也不靠归因才能跑。
- 不是制定策略的第五步，也不是决策者的前一步或后一步。前三步加决策者是同一段区间、同一份 version 上的一次模拟；决策者只是把这次资金回测用人再走一遍。Rolling 不读决策者的选择，也不挡住决策者。
- 系统不下「过拟合」「有时效」「稳定」这种结论，也不分析大环境。区间像不像，由配窗口的人负责。

## 2. 何时用

资金回测已经完成，用户也已经按归因把设置调好。Rolling 是这次回测之外的对照：当前设置冻住，只换区间。

使用上排在决策者前面更顺（先看机器结果换一段还像不像，再决定要不要亲手走这段）。入口独立，不插入四步步进器。

## 3. 配置

用户自己写窗口，起止日即可。重叠、包含、短于或长于原回测都可以，框架不限制、不改正。完全相同的窗口可以拒绝。

没有配窗口就不跑。原回测的起止日就是对照基准，不需要用户再写一遍。

## 4. 报告

基准是当前这次资金回测，不是第一段 Rolling，也不是「哪段收益最高」。

每一段一行，旁边是和基准的差值。用来比的是已经按时间对齐的数：最大回撤、夏普、Sortino、Calmar。账户总收益可以留下当原文，不拿它下「差多少」，因为窗口长短不同，总收益不在一个尺度上。

每一行标出这段多长、和原回测重叠多少。重叠会把两边的数往一起拉，读者需要看见这件事，才能判断差值是新区间带来的，还是同一段又算了一遍。

页面和终端都不出现结论句。

## 5. 相对现有实现还缺什么

已经有的：`sw` 能按 `attribution.rolling.windows` 把每段起止日盖到当前设置上，并跑到资金层。回撤、夏普、Sortino、Calmar 在资金报告里已经算得出来。窗口允许重叠（只拒绝完全相同的一段）。

还缺的：

| 已有行为 | 口径要求 |
|---|---|
| 窗口写在 `attribution.py`，和战役配置绑在一起 | 独立配置、独立入口；没有归因也能跑 |
| 报告落在 `results/attribution/{n}/rolling/` | 跟着这次回测，不跟归因组 |
| 差值相对第一段窗口，标题是哪段账户收益最好 | 差值相对当前这次资金回测；不排名 |
| 收集的是账户总收益、最大回撤、机会数 | 对照列换成最大回撤、夏普、Sortino、Calmar；总收益只作原文 |
| 不标重叠和窗口长度 | 每行标出长度，以及和原回测重叠多少 |
| 没有「必须先有一次资金回测」 | 没有基准回测就不跑 |
| 工作台没有入口 | 资金回测完成之后的独立入口，不进四步，不进决策者 |

收集侧目前只从资金摘要里取了总收益、胜率、最大回撤和资金占用。夏普、Sortino、Calmar 要补进这张对照，不必重算。
