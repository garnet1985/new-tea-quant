## 🔍 与 Stock-Based 模式对比

### 相同测试条件下的性能差异

| 维度 | Calendar-Sliced | Stock-Based (最优) | 比率 |
|:-----|:---------------:|:------------------:|:----:|
| **Wall Time** | **86.98s** | **27.66s** | **3.14x 慢** |
| **进程配置** | Reader=7, Compute=1 | 8 workers, epj=5 | - |
| **并行方式** | 时间切片并行 + 数据批量 | 股票批量并行 | - |
| **内存增量** | -83.4 MB | +21.6 MB | 切片更省内存 |
| **IO 特性** | IO 密集 (2.35:1) | IO 密集 (批量优化) | - |

### 适用场景对比

| 场景 | 推荐模式 | 原因 |
|:-----|:--------:|:-----|
| 因子选股、横截面研究 | ✅ **Sliced** | 天然按时间截面处理 |
| 行业轮动、定期再平衡 | ✅ **Sliced** | 匹配换仓周期 |
| 事件驱动、技术信号 | ✅ **Stock-Based** | 需要完整历史路径 |
| 大规模筛选 (>2000 股) | ✅ **Sliced** | 内存友好 |
| 复杂策略逻辑 | ✅ **Stock-Based** | 灵活性更高 |
